## 玩家能感受到的变化

- **保留自己的服务器列表。** 管理员启用 `serverList.enabled` 和 `mergePreferred` 后，更新器把指定服务器放到第一位，保留玩家的其他服务器和图标，并先备份旧文件。原 `servers.dat` 无法解析时不改写，提示手动添加；其余文件仍正常同步。
- **旧更新地址多一次恢复机会。** 地址文件里的地址全部失败后，同步引擎再尝试本实例保存过的成功地址和清单地址。恢复成功后可更新过期地址文件，并保留原文件备份。它不会凭空发现新地址；只有失效的局域网地址时，会明确提示向管理员索取最新文件。
- **重复检查更轻。** 文件校验结果可复用；清单使用 ETag 与本地缓存，服务端支持 gzip 和未变化时的 304 响应。需要下载的内容仍须通过哈希核验。
- **等待和报错更明白。** 更新窗口精简了说明，PowerShell 的分组更新记录逐行显示；连接、下载和修复提示更容易区分。官方源连续连接失败时会按规则回退，不保证每个网络环境都有相同速度提升。
- **入口和辅助脚本更一致。** 根目录入口优先调用 `_updater` 内的副本；macOS 增加可用 Python 检查及相关修复流程。实际启动器界面和游戏运行仍需要单独验证。

## 维护者能用到的变化

- `bump-updater-version.py` 统一更新各引擎副本的版本号，并检查是否一致。
- `release-updater.py new` 准备发布说明，`health` 按配置只读检查主机、文件、引擎版本和清单。发布步骤核对指定提交的 CI、内容发布锁及允许的文件漂移，并生成可追溯回执。
- 最新修正把 Windows 远程文件检查按每批 20 个路径拆分，减少命令超过 `cmd.exe` 长度限制的情况；这不等于任意长度参数都能执行。
- `update-adoption.py` 按访问日志汇总玩家更新器版本，访客编号每日变化，不把 IP 写入这份汇总。

这些工具需维护者自行提供主机配置；本仓库不附生产凭据或真实发布配置。
